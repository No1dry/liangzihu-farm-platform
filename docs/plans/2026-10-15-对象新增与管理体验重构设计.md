# 农业对象新增与管理体验重构 · 产品流程与界面设计

> **日期**：2026-10-15
> **依据**：`计划/梁子湖二维 GIS：农业对象新增与管理体验重构.md`
> **分支**：`m2b-object-management`，基于 `m2-map-editor` 顶端 `39cbf69`（M1、M2-A 均未经 main 合并，按任务书基于最新分支开发）
> **范围**：新增/管理体验重构 + M2-A 编辑安全小修；不做 M2-B 绘制扩展，不动设备业务系统

## 1. 现状审计要点

- 正式能力齐全但操作分散：`saveObject`（创建对象，code 唯一 409 `CODE_EXISTS`，创建者自动获 read+configure，`POST /api/v1/objects`→201）；`saveRegion`/`assignRegion`（`/api/v1/map-regions`，一对象一当前区域、关联历史自动保留）；归档接口齐备。
- 现状断点：新增农田要跳 `/objects` 填表 → 回总览在左栏折叠的 `RegionManagement` 里关联村庄 → 再去 `/map-editor` 画边界，三个页面脱节。
- `map-editor` 不支持 URL 预选对象；`canReview` 只看全局 scope 不看当前对象；Draw 交互绘制后不关闭可画多个面；切换对象无未保存保护（详见第 4 节修复落点）。

## 2. 信息架构（左目录 / 中央地图 / 右抽屉）

```text
┌────────────────────────────────────────────────────────────────┐
│ 页头：农场空间总览 ｜ 地图编辑 ↗ ｜ 原二维地图 ↗ …                 │
├──────────┬───────────────────────────────────────┬─────────────┤
│ 左目录    │ 中央地图（M1 底图体系）                │ 右操作抽屉   │
│ · 搜索    │ · 顶栏：目录/底图/图层/全场视图         │ （默认关闭） │
│ · 村庄 ▸  │ · ＋新增/管理 仍在目录顶部              │ · 新增村庄   │
│   [＋]   │ · 新增过程中地图视口与选中片区不动      │ · 新增对象   │
│ · 对象    │                                       │ · 更改归属   │
│ · 机动设备│                                       │ 标题/所属/   │
│ （可折叠）│                                       │ 取消/保存    │
└──────────┴───────────────────────────────────────┴─────────────┘
```

- **左目录只做导航**：村庄节点悬停/选中出现一个「＋」（发起该村下新增对象）；不出现常驻按钮组；目录内不再嵌入村庄维护表单（`RegionManagement` 的左栏折叠表单移除，功能迁入右抽屉）。
- **右抽屉按需出现**：新增村庄、新增对象、更改归属三种表单，统一骨架（标题、所属片区上下文、字段、取消/保存）；默认关闭，开关不改变地图视口。手机端为底部全宽面板。
- **专业绘制留在 `/map-editor`**：新增流程选择"现在绘制"→ 带 `?object=<id>` 跳转并自动选中；保存后返回总览恢复村庄与视口（沿用 M1 `saveReturnState`）。

## 3. 三条核心用户流程

### 流程 A：新增村庄

目录顶部「＋ 新增/管理」→「新增村庄」→ 右抽屉（所属农场只读、村庄名称、维护依据）→ 保存（`POST /api/v1/map-regions`）→ 目录刷新、新村自动选中展开 → 村庄节点下出现「新增第一个农业对象」入口（即该村「＋」）。村庄仅为经营分组，不生成边界。

### 流程 B：村庄下新增农田，稍后补位置

沙湾村「＋」→ 右抽屉「新增农业对象」：类型（农田/塘口/固定设施）、名称、编号（建议值 `村庄拼音化前缀-序号`，仅建议，可改；唯一性由后端 `CODE_EXISTS` 兜底并在表单提示）、登记依据（必填）、所属村庄（默认沙湾村可改）、边界选择「稍后登记位置」→ 保存：先 `POST /api/v1/objects` 创建，成功后立即 `PATCH /api/v1/map-regions` 关联村庄 → 目录刷新，新对象出现在沙湾村下，标记「待补位置」，不生成虚假几何。
异常：创建成功但关联失败 → 明确提示「对象已创建，村庄关联未保存」+「重试关联」按钮，不产生第二个对象；提交中按钮禁用防重复；编号冲突 409 时保留全部输入并提示改编号。

### 流程 C：村庄下新增农田，立即绘制边界

同流程 B，边界选择「现在绘制边界」→ 创建+关联成功后跳转 `/map-editor?object=<id>&from=farm-overview` → 编辑器自动选中该对象进入绘制 → 画不规则多边形、填来源依据、默认保存草稿 → 保存成功提示中提供「返回农场总览」→ 回到总览，沙湾村下看到带草稿边界的对象。
边界保存失败（对象已创建）→ 编辑器明示「对象已创建，边界未保存」，几何与表单保留，可重试或稍后从总览再进编辑器；对象身份唯一，不会重复创建。

## 4. M2-A 编辑安全小修落点（map-editor.tsx）

| # | 要求 | 实现 |
|---|---|---|
| 1 | 已核实边界修改默认草稿、来源重填、review 按当前对象 | `selectObject`：已核实对象进入编辑时 `status='draft'` 且 `source=''`（不再预填 boundary_source）；`canReviewSelected = scopes.some(s=>s.action==='review'&&s.objectIds.includes(selected.id))` 替换全局判断 |
| 2 | 409 不直接覆盖 | 409 后：保留本地几何；按钮变为「查看最新边界」（重拉数据、参考层显示当前正式边界、版本号更新展示）→ 用户确认后点「确认重新提交」才再次保存；不再是一键刷新即提交 |
| 3 | 单一待提交面 | `drawend` 后 `draw.setActive(false)`；「重新绘制」先 `clearInteractions()`；`onSave` 校验 editSource 恰好 1 个 feature，否则提示 |
| 4 | 未保存保护 | `editorState!=='idle'` 时：切换对象 / 取消编辑 / `beforeunload` 页面离开 → `confirm('有未保存的边界修改，确定放弃？')`；测试用 `page.on('dialog')` 处理 |
| 5 | 不规则五/六边形测试 | 浏览器测试改为绘制不规则六边形并保存，另拖顶点修改 |

## 5. 其他任务书要求的落点

- **更改所属村庄**：对象详情抽屉加「更改所属村庄」（有配置权时）→ 右抽屉显示当前村庄 + 新村下拉 + 确认 → 一次 `assignRegion`（服务端自动结束旧关联、写历史）→ 目录刷新。不要求用户手动两步操作。
- **固定设施登记**：同一新增面板选「固定设施」（kind=facility，保存走 `/objects`）；点位位置本轮不绘制，显示「稍后补位置」，不假造坐标；设备身份仍归 `/devices`。
- **机动设备**：总览维持只读目录 + `/machinery` 原入口，不新增绑定逻辑。
- **演示模式**：新增/管理在演示模式只读提示「退出演示后登记真实资料」（现状保留）；右抽屉表单只在真实模式可用。
- **权限**：所有写操作沿用原 API 的服务端校验；前端入口仅按 `/api/v1/objects?action=configure` 与 `/api/v1/me` 裁剪显示。
