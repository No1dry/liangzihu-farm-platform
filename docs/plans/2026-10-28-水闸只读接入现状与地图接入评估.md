## 2. 当前已经实现的水闸能力

### 2.1 MQTT 报文接入

| 文件 | 当前内容 |
|---|---|
| `src/adapters/gate/contract.ts` | 定义三诚闸门 MQTT 接入契约，包括设备主题、字段路径、测点映射、单位和质量语义 |
| `src/adapters/gate/adapter.ts` | 解析上行 JSON 报文，提取开度、设置开度、堵转电流等读数；`err` 按厂家确认修正为“非 0 即无效” |
| `src/modules/telemetry/gate-mqtt.ts` | 建立只读订阅、处理重连、写入遥测管线、推进游标；不把凭据写入数据库 |

| `tools/setup-gate.ts` | 登记数据来源、DTU、闸门实体设备、默认测点及预绑定；支持 `--device`、`--sn`、`--with-hydrology` |

## 6. 接入地图的推荐边界

后续如果把水闸接入 `/farm-overview`，建议遵循以下边界：

### 6.1 只读展示

地图只展示：

- 水闸设施位置
- 当前开度
- 设置开度
- 堵转电流
- 采样时间
- 数据质量
- 通信状态

不展示、不开放：

- 开闸
- 关闸
- 停止
- 远程控制
- 任何下行 MQTT 指令

### 6.2 数据模型

不新增 `objects.kind='gate'`。水闸继续使用：

```text
objects.kind = 'facility'
devices.kind = 'physical'
points.metric = 开度 / 设置开度 / 堵转电流
```

地图通过设施对象、实体设备、测点绑定和 `gate_deployments` 的关系识别“这是水闸”，再给地图返回 `symbol='gate'`。

### 6.3 前端展示

推荐最小改动：

1. 地图点位继续使用现有 `map-symbols.ts` 中已支持的 `gate` 图标。
2. 资源树中显示“水闸”文本提示，但不新增控制菜单。
3. 右侧详情栏在“基本信息”展示真实编号、所属农场、所属村庄、边界状态、登记依据。
4. “关联设备”标签页展示当前值和采样时间。
5. 提供“查看关联设备”入口到 `/devices`。
6. 不提供控制按钮。

### 6.4 后端接口

有两种可选方式：

| 方案 | 做法 | 优点 | 风险 |
|---|---|---|---|
| A | 扩展 `/api/v1/farm-overview`，直接返回 `gateStatuses` | 地图一次请求即可完成 | 需要改地图总览服务 |
| B | 详情栏选中水闸后调用 `/api/v1/points/current` | 改动更小，复用对方接口 | 选中后有第二次请求 |

建议先采用 **方案 B**，因为它不扩大地图列表接口的数据量，也更容易保留当前地图性能。

## 7. 安全与权限边界

必须保留：

- 未登录不能读取水闸状态。
- 没有对象 `read` 权限不能看到水闸位置与状态。
- 未验证的测点绑定不能作为真实状态展示。
- 没有 `configure` 权限不能登记设备、测点或部署资料。
- 没有 `act` 权限不能创建控制申请。
- 不绕过 `source_health`、绑定验证和遥测质量标记。
- MQTT 凭据只放 `.env.local` 或私有配置，不进入 Git。
- 原始报文入库前继续执行凭据扫描，发现敏感字段时拒绝或隔离。
