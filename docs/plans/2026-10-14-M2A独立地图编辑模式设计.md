## 1. 现状审计结论（复用与缺口）

### 可直接复用（不重造）

| 能力 | 位置 | 复用方式 |
|---|---|---|
| 正式边界保存 `saveBoundary(c,actor,body)` | `src/modules/map/service.ts:8` | `POST /api/v1/map`，字段 `{objectId,version,sourceCrs,geometry,status,source}`；成功返回 200；内部写 `objects.boundary`+版本递增、`boundary_versions` 历史、`object_versions` 快照 |
| 权限链 | 同上 `:9,:12` | 保存需对象级 `configure`；`status:'verified'` 另需 `review`，后端强制 403 |
| 几何校验与 SRID | `src/modules/map/geometry.ts:2` | 支持 4326/4490/3857 输入、统一存 4326；仅 Polygon/MultiPolygon；非法几何 400/422 |
| 版本冲突 | service 层 | 409 `VERSION_CONFLICT`；前端保留几何、提示后重试 |
| 可配置对象清单 | `GET /api/v1/objects?action=configure` | 决定编辑器的可选对象（前端入口裁剪；服务端仍强校验） |
| 已授权对象+边界+版本 | `GET /api/v1/farm-overview` | 编辑器地图底图层与选中对象版本来源 |
| 角色 scopes | `GET /api/v1/me`（`/map` panel.tsx:14 已有用法） | 判断是否显示「提交已核实」选项 |
| M1 视觉体系 | `farm-overview/map-symbols.ts`、`layer-panel.tsx`、`tianditu.ts`（vec/cva/img/cia） | 编辑器同一套底图切换、分类样式、选中高亮 |
| 绘制交互范式 | `map-prototype/satellite-prototype.tsx`（modeRef、IME、Esc、临时 source）；`farm-overview.tsx:104`（Draw + 3857→4326 回写样板） | 编辑器交互照此实现 |

### 缺口（本轮新建）

- `/map-editor` 路由与页面；侧边导航「空间与资料」分组加「地图编辑」入口（worker/expert 导航集合不加入，页面内再按对象级 configure 控制）。
- 可视化多边形 Draw + 顶点拖动 Modify + 临时预览 layer（旧 `/map` 只有 GeoJSON 文本表单）。
- 从 `/farm-overview` 页头进入编辑器、保存后返回总览（总览会话状态恢复沿用 M1 机制）的路径。

### 明确不做

不改 `saveBoundary` 与数据模型；不支持 LineString；不为幂等新增 `requestKey`（以前端提交中禁用按钮防重，重复提交风险在验收记录注明）；不新建对象（跳 `/objects` 原流程）；worker/expert 不可见导航入口且服务端 403 兜底。

## 2. 页面与交互设计

```
/map-editor
┌ 页头：地图编辑 · M2-A ｜ 返回农场总览 ↗ ｜ 去对象台账新建 ↗(跳 /objects) ┐
├ 左栏（对象选择）                                                      ┤
│  · 可配置对象列表（field/pond，来自 action=configure ∩ 总览授权数据）   │
│  · 每项显示：名称、编号、边界状态（已核实/草稿/待登记）、版本            │
│  · 无 configure 权限：明示"没有可编辑对象"，列表为空，不显示工具         │
├ 地图（M1 底图体系：默认矢量，可切卫星；注记开关；图例）                  │
│  · 只读参考层：全部已授权对象边界（M1 分类样式）                        │
│  · 编辑层：选中对象边界高亮 + 顶点手柄；或绘制中的临时面（草稿样式）      │
│  · 工具条：绘制新边界 / 修改顶点 / 取消编辑                            │
├ 右下编辑表单（选中对象后出现）                                         │
│  · 对象名/当前版本；边界状态选择：草稿（默认）/已核实（仅 review 权限）   │
│  · 来源依据（必填文本，≤2000）；保存/取消按钮                           │
└──────────────────────────────────────────────────────────────────────┘
```

**交互规则**：

1. 选择对象 → 地图定位到其边界（无边界则定位到梁子湖默认区并提示"待登记边界，请绘制"）。
2. 「修改顶点」：Modify 交互拖动已有顶点；「绘制新边界」：Draw 画新多边形（双击结束，≥3 顶点，自交由服务端校验兜底）。
3. 编辑中几何只存在于临时 VectorSource，样式用草稿虚线 + 选中高亮；点击「保存」才 POST。
4. 保存成功 → 提示、重新拉取服务端数据、退出编辑态，地图显示最新正式边界；保存失败（409/403/400/网络断）→ 临时几何与表单原样保留，错误语义明确（版本冲突提示"他人已更新，已为你保留未提交几何，刷新版本后可重试"）。
5. 「取消」/Esc → 清空临时几何，数据库零变化。
6. 中文 IME：`isComposing` 守卫沿用 map-prototype 模式。
7. 移动端：本轮编辑器保证可用（目录抽屉式选择 + 底部表单），精细触控绘制体验不属 M2-A 验收重点。

**坐标纪律**：提交前 `GeoJSON.writeGeometryObject(featureProjection:'EPSG:3857',dataProjection:'EPSG:4326')`，`sourceCrs=4326`。

**版本纪律**：保存用列表返回的 `version`；409 后重新拉取再允许重试；verified 选项只在 `/api/v1/me` 含 review scope 时出现。

## 4. 测试计划（对应任务书十项验收）

新增 `tests/acceptance/map-editor-browser.test.ts`（Playwright，隔离库）：

1. 选已有农田 → 修改顶点（由 `data-view-center/view-resolution` + 已知顶点经纬度换算像素，mouse down/move/up）→ 保存 → 成功提示，DB 边界已变。
2. API 新建正式塘口主档 → 编辑器绘制不规则多边形 → 保存为草稿 → `boundary_status='draft'`。
3. 刷新页面重新进入 → 边界与 DB 一致（比较 `ST_AsText` 或 GeoJSON 坐标）。
4. `boundary_versions` 行数增加、旧版本仍在（历史不覆盖）。
5. 无 configure 账号：列表为空 + 直接 POST 403。
6. 无 review 账号：UI 不出现「已核实」选项；强制 POST verified → 403。
7. 版本冲突：编辑中由另一会话更新版本 → 保存 409 → 临时几何保留、提示明确 → 重读版本后重试成功。
8. 取消绘制/修改 → DB 无变化（版本与边界不变）。
9. 回归：`/farm-overview`、`/map-prototype`、`/terrain` 既有浏览器测试全绿。
10. `typecheck`、`build`、`test:unit`、`test:db` 结果记录。

浏览器地图像素换算：编辑器地图容器沿用 M1 的 `data-view-center`（EPSG:3857）并补 `data-view-resolution`；测试以 Web Mercator 公式将顶点经纬度换算为像素坐标后执行拖拽。
