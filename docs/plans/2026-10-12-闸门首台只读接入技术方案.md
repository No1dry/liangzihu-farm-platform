# 闸门首台只读接入技术方案（hbdxscz001）

> 版本：2026-10-12 初稿。用途：平台方与闸门厂家（三诚，联系人高工/倪工）协商第一台闸门 hbdxscz001 的真实接入。读者为厂家工程师与项目成员。文中所有"待厂家确认"事项均未核实，不作为事实；平台侧行为以所引源码路径为准。
>
> 配套协议事实详见[三诚闸门只读 MQTT 接入契约状态](../contracts/gate-sdsc.md)；本文侧重"怎么连、怎么联调、出问题怎么退"。

## 1. 背景与目标

项目共有三诚 SCZM-LG 单螺杆闸门 29 台（编号 hbdxscz001~029，固件 VER:V2.4.05.000000.0000）。首台接入对象为 hbdxscz001：单螺杆 300 型、规格 300-1.4，SN 00601925123000009360（IMEI/ICCID 见附件一，本文不抄录）。

第一阶段目标**只读**：把闸门自动上行的开度、水位、流量等测值收进平台并展示，**不做任何远程控制**。先只读的原因：

- 只读接入风险最低，即使链路出错也不会影响闸门现场运行；
- 平台采集、解析、入库、展示链路已经实现并完成工程测试，缺的是真实 broker 地址和厂家把 DTU 指过来；
- 下行查询/控制（rw_prot、写 setOpening 等）协议已拿到，但作为后续阶段单独设计和验收，本期代码中没有任何下行路径。

- 上行（设备推送，每台一个）：`/sdscdevice/gate/hbdxscz260302/publish/hbdxsczXXX`
- 下行（平台下发，本期不用）：同路径 `publish` 换 `sub`
- XXX = 001..029，29 台仅尾号不同。

## 3. 上行报文格式详解

设备按设定间隔自动上行一条 JSON（厂家协议 PDF 样例，注意样例中的 sys_sn/sys_imei 是文档示例值，不是首台设备的真实值）：

```json
{"params":{"dir":"up","id":"1728629601","sys_sn":"02700124091000013038","sys_imei":"865661071299476","sys_time":"1728629601","r_data":[
 {"name":"currentMax","value":10006},
 {"name":"pulseEquivalent","value":0},
 {"name":"opening","value":0},
 {"name":"setOpening","value":0},
 {"name":"cumulativeFlows","value":0},
 {"name":"waterLevel","value":0},
 {"name":"instantaneousFlow","value":0}]}}
```

逐字段说明：

| 字段 | 位置 | 含义 | 平台处理 |
|---|---|---|---|
| dir | params | 方向，上行固定 `"up"` | 不是 `"up"` 不解析 |
| id | params | 报文标识，Unix 秒 | sys_time 缺失时兜底作采样时间 |
| sys_sn | params | 设备 SN，可不携带 | 参与原始报文标识组合 |
| sys_imei | params | 设备 IMEI，可不携带 | 同上 |
| sys_time | params | 采样时间，Unix 秒 | 优先作采样时间 |
| r_data | params | 测值数组 | 平台限制 ≤ 1000 行 |
| name / value | r_data 元素 | 字段名 / 数值 | value 支持数字或数字字符串；见下表 |
| err | r_data 元素 | 字段错误标记，如 `"err":"1"` | 该字段 value 置空、quality 记 invalid、原始值保留 |

r_data 内七个字段的含义（厂家协议 PDF）：

| name | 含义 | 单位 | 备注 |
|---|---|---|---|
| currentMax | 堵转电流 | mA | 内置螺杆闸门用 |
| pulseEquivalent | 脉冲当量 | — | 平台未登记为测点，出现时跳过 |
| opening | 当前开度 | % | |
| setOpening | 设置开度 | % | 本期只读，不回写 |
| cumulativeFlows | 累计流量 | m³ | 位数/溢出行为**待厂家确认** |
| waterLevel | 水位 | mm | |
| instantaneousFlow | 瞬时流量 | m³/s | |

时间戳规则：采样时间取 sys_time（Unix 秒），缺失时用 id 兜底；两者都缺时平台**不拿收到时间伪造**，该测值 quality 降为 suspect 并记 unknown_sample_time。

err 处理：某字段带 `"err":"1"` 时，平台保留原始值（rawValue）、有效值置空、质量记 invalid（vendor_field_error），不会影响其他正常字段入库。err 除 `"1"` 外是否还有其他取值**待厂家确认**。

## 4. 平台内部处理流程

![图2 报文处理流程](assets/2026-10-12-闸门首台只读接入/图2-报文处理流程.svg)

（可编辑源文件：[图2-报文处理流程.mmd](assets/2026-10-12-闸门首台只读接入/图2-报文处理流程.mmd)）

各环节与代码对应：

1. **主题取设备号**：`gateDeviceFromTopic`（`src/adapters/gate/adapter.ts`）从主题最后一段取设备编号并校验字符集；订阅主题（下行方向）来的报文直接拒绝。
2. **契约检查**：私有契约 JSON（路径由 `GATE_CONTRACT_FILE` 指定，含 sourceId/actorId/authVersion/测点映射，不入库不入仓）verified=false 时整体拒绝（GATE_CONTRACT_NOT_READY）——即未核实的配置一条数据都进不来。
3. **解析**：`normalizeGate` 要求 dir="up"、r_data 为 ≤1000 行的数组；时间戳、err、非数字按第 3 节规则处理。
4. **映射唯一性**：`externalDeviceId + metric` 必须唯一命中一条测点映射，缺失或重复整体拒绝（UNMAPPED_DEVICE），不取第一项凑数。
5. **入库前 guard**：每次入库前检查来源 verified=true、provider='sdsc'、契约版本一致、操作主体未撤权、测点绑定对象授权；不通过进隔离区。
6. **幂等入库**（`persistBatch`，`src/modules/telemetry/ingest.ts`）：
   - `raw_receipts`：原始报文原文存档（sha256），**拒绝含凭据键的报文**；
   - `observation_heads` / `observations`：按 identity_hash + content_hash 幂等去重，broker 重投、进程重启不会造成重复数据；
   - `point_current`：仅当测点绑定 verified 且新鲜度、质量检查通过时才更新"当前值"，网页看到的就是这里；
   - `quarantined_readings`：解析失败、未映射、未核实绑定的测值全部进隔离区留痕，不丢、不混进正式数据；
   - `ingestion_cursors`：只记最近采样时间作断点参考（MQTT 推送无分页，**不做漏报补拉**）；
   - `source_health`：心跳与可用性；`domain_events`：领域事件。
7. **运行防护**：advisory lock `gate-mqtt:<sourceId>` 防止同一来源重复启动采集进程；出错心跳记 unavailable。

离线核对能力：`pnpm worker:gate --replay 契约文件 报文信封文件` 可把保存的报文信封（`{"topic":"...","payload":{...}}`）离线回放走完整入库流程；`--synthetic-replay` 合成报文只能进测试库。联调时用真实脱敏报文回放核对，不依赖设备实时在线。

测试现状：6 组单元测试 + 集成测试（持久化、重投去重、撤权拒绝、malformed 隔离、下行主题拒绝），均使用合成契约与合成报文；真实设备联调尚未执行。

## 5. 测点映射与单位表

登记工具 `pnpm registry:gate`（`tools/setup-gate.ts`）登记：1 个数据来源、1 个 DTU（gateway）、1 台闸门（physical，SCZM-LG，SN 00601925123000009360）和 6 个测点，**全部 verified=false**，须现场核实后由授权人员置真。

| 报文字段 | 平台测点 code（首台） | 单位 | 换算 |
|---|---|---|---|
| opening | GATE-001-OPENING | % | scale=1 / offset=0 |
| waterLevel | GATE-001-WATER-LEVEL | mm | scale=1 / offset=0 |
| instantaneousFlow | GATE-001-INSTANT-FLOW | m³/s | scale=1 / offset=0 |
| cumulativeFlows | GATE-001-CUMULATIVE-FLOW | m³ | scale=1 / offset=0 |
| setOpening | GATE-001-SET-OPENING | % | scale=1 / offset=0 |
| currentMax | GATE-001-STALL-CURRENT | mA | scale=1 / offset=0 |

注意：**当前所有换算为 scale=1/offset=0（原值入库）**，真实换算参数待现场读数比对核实后再调整。pulseEquivalent（脉冲当量）未登记为测点，报文中出现即跳过。

## 6. 单中心限制与 broker 切换方案（重点）

**关键约束：设备只支持单中心上报。** DTU 指向我方 broker 后，原厂家平台即断连，两者无法并存。设备平台接入信息可修改。因此切换时机必须和现场/厂家事先约定，且必须有回退方案（DTU 指回厂家 broker 参数）。

![图3 broker 切换方案](assets/2026-10-12-闸门首台只读接入/图3-broker切换方案.svg)

（可编辑源文件：[图3-broker切换方案.mmd](assets/2026-10-12-闸门首台只读接入/图3-broker切换方案.mmd)）

方案对比：

| | 方案 A：DTU 直指我方 broker（建议首选） | 方案 B：厂家平台转发（备选） |
|---|---|---|
| 做法 | 厂家远程或现场修改 DTU 平台接入信息，指向我方 broker | 设备保持连厂家平台，厂家平台经 API/MQTT 把上行数据推送给我们 |
| 平台侧改动 | 无新增开发，现有 worker 直接可用 | 需新增接收适配，报文格式以厂家转发为准 |
| 厂家侧工作量 | 改一次 DTU 参数（设备支持修改接入信息） | **需要厂家平台开发转发功能，是否支持待厂家确认** |
| 厂家平台影响 | 切换期间厂家平台看不到该设备数据 | 无影响 |
| 数据时效/完整性 | 原始报文直达，字段无损耗 | 取决于厂家转发的字段与频率 |
| 回退 | DTU 指回厂家 broker 参数即可 | 停止转发即可 |

切换与回退步骤（方案 A）：

1. 双方约定切换窗口（建议白天、现场有人值守时）；
2. 切换前我方完成 .env.local 与私有契约配置、worker 就绪（先不置 verified）；
3. 厂家将 DTU 指向我方 broker，观察首条上行报文是否到达；
4. 任一步不通过：厂家把 DTU 指回厂家 broker 参数，恢复现状，问题排查后再约窗口。

## 7. 联调实施步骤

![图4 联调时序](assets/2026-10-12-闸门首台只读接入/图4-联调时序.svg)

（可编辑源文件：[图4-联调时序.mmd](assets/2026-10-12-闸门首台只读接入/图4-联调时序.mmd)）

各步骤检查点与通过标准：

| 步骤 | 责任方 | 动作 | 通过标准 |
|---|---|---|---|
| 1 | 我方 | `pnpm registry:gate` 登记来源/DTU/闸门/6 测点 | 台账可查，verified 全为 false |
| 2 | 我方 → 厂家 | 提供 broker 地址、端口、客户端 ID 规则；MQTT 账号密码经安全渠道单独交付，**不经聊天明文、不入仓库** | 厂家确认收到且能配置 |
| 3 | 我方 | 配置 .env.local（GATE_MQTT_ENABLED、GATE_MQTT_URL、GATE_MQTT_CLIENT_ID、GATE_CREDENTIAL_USERNAME/PASSWORD）与私有契约文件 | worker 能连上 broker 并完成订阅 |
| 4 | 厂家 | 约定窗口内修改 DTU 指向我方 broker | DTU 上线，broker 侧看到客户端接入 |
| 5 | 我方 | 启动 `pnpm worker:gate` 接收首条真实上行报文 | raw_receipts 有原文、observations 有 6 个测点观测 |
| 6 | 我方 | `--replay` 回放保存的真实脱敏报文 | 回放结果与实时入库一致，重放不重复 |
| 7 | 双方 | 现场读数比对：闸门当前开度、水位等与平台数值逐项对照 | 读数一致或差异可解释（换算参数此时核实） |
| 8 | 我方（授权人员） | 核实后来源与测点 verified 置真 | point_current 更新，`/devices` 页面自动展示数值与曲线 |
| 9 | 双方 | 首台稳定运行后按同法复制到 hbdxscz002..029 | 复制前先核对 002..029 编号台账 |

任一步不通过即回退：DTU 指回厂家 broker 参数，恢复厂家平台连接。

## 8. 只读边界与安全纪律

- **本期不实现任何下行**：不订阅处理结果之外的任何下发动作，代码中没有下行 publish 路径或开关闸命令构造。下行查询/控制（rw_prot 包装、Ver "1.0.1"、dir="down" 下发 / dir="rsp" 应答、id 原样回传核对；控制即写 setOpening，全开=100 全关=0；Modbus 寄存器 0011 写 0 停止 / 写 1 继续）属后续阶段，届时单独设计、单独验收。注意协议细节：应答报文 value 是字符串（如 `"35"`），上行 value 是数字，平台解析两者均支持。
- **verified 三级硬门**：契约 verified=false → 拒绝解析；来源/绑定未 verified → 入库 guard 拦截进隔离区；测点绑定未 verified → 不更新 point_current。任何一级未过，数据都不会被当成"真实设备数据"展示。
- **凭据管理**：MQTT 账号密码只放 .env.local（仓库已忽略），契约文件、文档、CHANGELOG 均不写入凭据；raw_receipts 入库时还会拒绝含凭据键的报文。本文及附件一台账中的账号信息按保密资料管理。

## 10. 风险与未决事项

| 风险/未决项 | 影响 | 缓解 |
