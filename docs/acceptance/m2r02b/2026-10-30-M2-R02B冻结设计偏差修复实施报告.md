## 1. 整改前后行为对照（逐项引用冻结要求）

### 1.1 农田顶部（农田 V1 §一.1、§2.3）

| 冻结要求 | 整改前 | 整改后 |
|---|---|---|
| 面积→当前生产→生长阶段固定顺序、固定卡位 | 批次行在面积前，阶段合并在批次行内 | **面积（含口径说明）→「当前生产：…」独立行 →「生长阶段：…」独立行**，顺序有浏览器断言（`indexOf` 顺序检查） |
| 有记录但未核实：顶部不展示具体作物与阶段，显示「资料待核实」 | 顶部显示「生产批次尚未核实：小麦 · 抽穗期」 | 顶部只显示「当前生产：资料待核实」「生长阶段：资料待核实」；**具体品种/阶段不出现在顶部**（断言 count=0），原登记值仍在「农事生产」标签可见 |
| 完全无生产记录：显示「暂无登记」 | 「暂无生产批次登记。」 | 「当前生产：暂无登记」 |
| 范围未登记：面积显示「暂无参考面积」，绝不显示 0 | 整行消失 | 农田显示「暂无参考面积」、塘口显示「暂无可信范围面积」 |

### 1.3 空间状态徽标（横向 §2、§5.1、水闸 G9）

| 冻结要求 | 整改前 | 整改后 |
|---|---|---|
| 农田/塘口：范围未登记/待核对/已核实 | 统一「已核实/草稿/待登记」 | 农田/塘口显示**范围未登记/范围待核对/范围已核实** |
| 水闸/泵站（设施）：位置未登记/待核对/已核实，不套地块边界语义 | 同上 | 固定设施显示**位置未登记/位置待核对/位置已核实** |
| 不得仅凭几何或字段名推断已核实 | — | 徽标仅按 `boundary_status` 三态映射（`scopeBadge`，含单测） |

基本信息标签内的「边界状态」行同步改为「范围状态/位置状态」同义值。

### 1.4 塘口多测点（塘口 V1 §2.4）

- 冻结要求：同一指标多个测点没有经确认的代表点时，顶部不输出任意单一数值，显示「多个测点·查看详情」。
- 整改前：`pickTrustedIndicators` 直接取前两个可信值（同指标也取）。
- 整改后：`buildTopIndicators` 按指标分组——单可信测点取值，多可信测点显示「N 个测点，未指定代表测点 · 查看详情」（点击切到水体监测标签）；最多两个指标位置。单测覆盖。

### 1.5 信息误导修复（要求 5）

- 「暂无参考面积」补位（见 1.1），不再以整行缺失含糊表达；
- 计数卡（农事记录/关联测点）仅在概要真实存在时渲染，避免概要缺失时显示 0 造成误读；
- 批次读取失败显示「读取失败 + 重试」而非空态；无权限显示「暂不可查看」。

## 4. 新增产品意见（未实施，最小 V1 修订建议，待确认）

1. **对象编号弱化**：基本信息中「对象编号」对普通工作人员价值低，建议降级入「资料依据」，仅保留名称与归属。
2. **缺失字段集中空态**：负责人/现场位置说明/用途等无来源字段，建议在基本信息以一行「以下资料待补充登记」集中呈现，替代逐行「暂无登记」，减少阅读噪音。
3. **详情信息进一步精简**：计数卡（农事记录/关联测点）建议移出顶部摘要、归入对应标签，顶部只保留 V1 规定的核心业务事实。

以上 3 条未实施，需产品确认后再动。
