## 1. 树组件选型与兼容性

| 项目 | 结果 |
|---|---|
| 组件 | `@rc-component/tree@1.5.3`（MIT） |
| 兼容 | `peerDependencies: react:'*'`，与 React 19 / Next.js 16 无版本冲突；`pnpm add` 成功，`tsc --noEmit` 通过，生产构建通过 |
| 引入方式 | 纯客户端组件，`treeData` 驱动；`titleRender` 自定义节点内容；受控 `expandedKeys`/`selectedKeys`；`onRightClick`、`scrollTo`；样式 `assets/index.css` |
| 备选 | react-arborist 需 react-dnd，依赖更重；首选无兼容障碍，未同时安装第二套树组件 |

数据仍来自现有 `objects`、`map_regions`、`map_region_links` 与既有授权 API；组件只负责树形 UI。节点 key 使用 `farm:<id>`、`region:<id>`、对象 UUID、`unassigned:<farmId>`，未使用数组下标，未把目录层级写回 `objects.parent_id`。

## 2. 新旧目录结构对比

| 维度 | 旧目录（手写 section + ul） | 新目录（@rc-component/tree） |
|---|---|---|
| 层级 | 村庄是分组标题，不是真正的树 | 农场 → 村庄 → 对象真树形，箭头独立展开/折叠 |
| 定位 | 点击主要改变高亮，部分情况下只平移 | 对象/村庄统一 `view.fit()` 定位，含抽屉 padding、maxZoom、300ms 动画 |
| 操作入口 | 村庄旁常驻「＋」 | 节点 `···` 悬停/聚焦/触摸及右键菜单，按节点类型与权限分发 |
| 删除恢复 | 无 | 「移至回收站」软归档 + 确认；目录底部回收站查看与恢复 |
| 搜索 | 过滤列表 | 命中子节点时保留父级并临时展开，清空恢复原展开状态 |
| 状态 | 查询/选中/视口 | 增加 `expandedKeys` 持久化；模式切换及演示隔离仍保持干净状态 |

## 4. 数据库验证

| 检查 | 结果 |
|---|---|
| `objects` 归档 | 农田/塘口/facility 均为软归档，只更新 `archived_at` 等字段并保留对象与版本历史，不执行物理删除 |
| facility 归档能力 | `setObjectArchive` 允许类型扩展为 `['field','pond','facility']`；全库相关外键均为默认 NO ACTION，无级联删除或阻塞；归档/恢复集成测试通过 |
| `map_region_links` | 归档村庄时结束当前关联但保留历史行；恢复村庄不自动重建关联 |
| 改归属 | 原关联 `valid_to` 非空，新关联 `valid_to IS NULL`，两条历史均可查 |
| 权限 | 归档、恢复、修改归属均沿用原服务端 configure 校验；直接越权 POST 返回 403 |

## 6. 已知问题与边界

- `listMap` 仍保留既有 `LIMIT 500`，页脚已明示；本轮未实现分页加载，后续数据规模接近上限时需另行设计。
- 恢复对象不会自动恢复已结束的村庄关联，界面已有说明；如需重新分配，应通过「更改所属村庄」操作。
- 固定设施只提供与现有真实业务能力一致的菜单，不提供边界绘制或设备控制入口。
- 本轮未实现永久删除；如需管理员专用永久清理，应另行做依赖检查与专门设计。
- 移动端采用可关闭目录抽屉，未实现专业 GIS 触控绘制。
